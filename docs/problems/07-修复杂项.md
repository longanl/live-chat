# 07 · 修复杂项

## 1) WebSocket 写入时逐条查用户（N+1）

`WebSocketServer.onMessage` 每收到一条消息都执行一次 `select * from users where id=?`
拿发送者昵称/头像。

**方案**：会话化后保留该查询为点查（`users.id` 主键命中，成本极低）；若未来压力扩大，
可把发送者昵称/头像放到一次性 join（历史查询已 join），或用本地 Map 缓存。当前不改。

## 2) users.status 在线扫描

`queryOnlineUser` 为 `select * from users where status=1`，无索引全表扫。

**方案**：`users` 加 `KEY idx_status(status)`（已随 05 一并落地）。

## 3) 好友操作两条 SQL 未走事务

`FriendsMapper.insert / update / delete` 都含**两条** SQL（正向 + 反向关系），
单条失败对端状态会不一致。

**方案**：`FriendsServiceImpl` 的 `add / approve / reject / delete` 加 `@Transactional`
（add/approve/reject 已有，`delete` 本次补上）。见 `FriendsServiceImpl.delete`。

## 4) 排序一致性

旧历史查询 `order by send_time`，同秒消息顺序不稳定（无唯一序）。

**方案**：新方案按 `order by id desc` 游标分页，`id` 单调唯一，翻页分桶稳定。

## 5) 遗留清理

- `chat_messages.file_id`、`read_status` 随重构删除；
- 前端 `parseFileContent` 保留作老数据兜底，新消息直接读 `fileUrl` 等字段。
