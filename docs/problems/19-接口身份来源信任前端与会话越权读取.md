# 19 · 接口身份来源信任前端，私聊会话可越权读取

> 安全专项：接口身份来源收口 + 会话成员校验。

## 问题

- `userId`/`id` 由路径或 body 传入，后端零校验直接采信：`/messages/unread/{userId}`、`/friends/list/{id}`、
  `/users/logout/{id}`、改密/改资料/好友审批 DTO 均带身份字段；
- 私聊 `history` 只按 `conversationId` 查询，无成员校验，可枚举会话 ID 越权读取他人私聊；
- `markRead` 附带 `insertMember`，攻击者"标记一次已读"即可把自己加入任意会话（可自我扩权）。

## 解决

- 新增 `BaseContext`（ThreadLocal）承载当前用户 id；`JwtTokenInterceptor` 解析 JWT 的 `claims.id` 写入，
  `afterCompletion` 清除，防线程池复用串号；
- REST 全量移除前端传入身份：`/messages/unread`、`/messages/read`、`/friends/list|require`、`/users/logout`
  不再带身份参数；`AddFriendDTO`/`RelationshipDTO`/`PasswordDTO`/`ProfileDTO` 删除 `userId`/`id` 字段，
  一律取 `BaseContext.getCurrentId()`；
- `history` / `markRead` 增加会话成员校验（`selectConversationMember`，命中 `uk_conv_user` 索引），
  非成员抛 `BusinessException("无权访问该会话")`；**删除** `markRead` 的 `insertMember`；
- 前端 `api/**`、`stores/chat.ts`、`views/layout.vue`、`views/contact.vue` 同步移除身份实参。
