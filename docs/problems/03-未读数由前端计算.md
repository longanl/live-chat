# 03 · 未读数由前端遍历全量 history 计算

## 问题

`stores/chat.ts` 的 `getUnreadCount(friendId)` 在**前端内存**里线性扫描整个 `history`：

```ts
for (let i = 0; i < history.value.length; i++) {
  if (history.value[i].senderId === friendId
   && history.value[i].receiverId === currentUser.value.id
   && history.value[i].readStatus === 0) count++;
}
```

依赖两个前提，两者在 01 的改造后都不再成立：

1. 前端必须持有**该好友的全部消息**才能数对未读；
2. 每条消息都要维护 `read_status` 并频繁 `update set read_status=1 ...`。

## 方案：`conversation_members.last_read_msg_id` 已读游标 + 服务端统计

- 每条用户会话存一个游标 `last_read_msg_id`（已读到的最大消息 id）；
- **未读数量** = 该会话中 `id > 游标 且 sender != 我` 的消息数，完全由后端统计：

  ```sql
  select m.conversation_id, count(*) as cnt
  from chat_messages m
  join conversation_members me
    on me.conversation_id = m.conversation_id and me.user_id = #{userId}
  where me.last_read_msg_id < m.id and m.sender_id <> #{userId}
  group by m.conversation_id;
  ```

- **标记已读** = 打开会话时把游标推进到该会话当前最大 `id`：

  ```sql
  update conversation_members
  set last_read_msg_id = #{lastReadMsgId}
  where conversation_id = #{conversationId} and user_id = #{userId};
  ```

收益：未读数不依赖前端持有多少消息，O(1) 位移一句话；也不必再为每条消息回填 `read_status`。

## 接口

- `GET /messages/unread/{userId}` → `[{conversationId, count}]`
- `POST /messages/read` body `{conversationId, userId}` → 推进已读游标

- ✅ 后端：`selectUnread` / `markRead`（MessagesMapper + Service + Controller）
