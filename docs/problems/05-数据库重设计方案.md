# 05 · 数据库重设计方案

> 正文即"新结构"：4 张表。DDL 以及从旧库迁移/回滚的 SQL 见 **06-迁移与回滚.md**。
> `chat.sql`（`backend/src/main/resources/chat.sql`）已更新为该结构的全新建库脚本。

## ER 摘要

```
users ────────────────┐
  │ (成员)             │
  ▼                    │
conversation_members ──┼──► conversations (1 私聊 / 2 群聊)
  │                     │
  │ conversation_id     │ conversation_id
  └──► chat_messages ──┘
```

- **conversations**：会话本体。私聊一个成员对一条，群聊全站内置一条（“技术讨论群”，id=1）；
- **conversation_members**：用户与会话的多对多，同时携带已读游标 `last_read_msg_id`；
- **chat_messages**：消息本体，归属会话，文件元数据为独立列；
- **users**：沿用旧结构，仅增加 `status` 索引（在线打点）；
- **friend_relations / friend_requests**：好友关系表拆分为"关系 + 申请"两个表（见 08）。

## 表结构

### 1. users（微调）

| 列 | 类型 | 说明 |
|----|------|------|
| id | bigint PK AI | |

索引：`PRIMARY KEY (id)`、`UNIQUE (username)`、新增 `KEY idx_status (status)`。

### 2. conversations（新）

```sql
CREATE TABLE `conversations` (
  `id` bigint NOT NULL AUTO_INCREMENT,
  `type` tinyint NOT NULL COMMENT '1-私聊 2-群聊',
  `name` varchar(100) DEFAULT NULL COMMENT '群聊名称；私聊为空',
  `owner_id` bigint DEFAULT NULL COMMENT '群主用户ID；私聊为空',
  `create_time` datetime DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  KEY `idx_type` (`type`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

### 3. conversation_members（新）

```sql
CREATE TABLE `conversation_members` (
  `id` bigint NOT NULL AUTO_INCREMENT,
  `conversation_id` bigint NOT NULL,
  `user_id` bigint NOT NULL,
  `last_read_msg_id` bigint NOT NULL DEFAULT 0 COMMENT '已读游标：已读到的最大消息id',
  `join_time` datetime DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_conv_user` (`conversation_id`,`user_id`),
  KEY `idx_user` (`user_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

### 4. chat_messages（重构）

```sql
CREATE TABLE `chat_messages` (
  `id` bigint NOT NULL AUTO_INCREMENT,
  `conversation_id` bigint NOT NULL COMMENT '所属会话',
  `sender_id` bigint NOT NULL COMMENT '发送者ID',
  `message_type` tinyint NOT NULL DEFAULT 1 COMMENT '1-文本 2-文件',
  `content` text NOT NULL COMMENT '文本正文（文件消息可为说明文字）',
  `file_url` varchar(255) DEFAULT NULL,
  `file_name` varchar(255) DEFAULT NULL,
  `file_size` bigint DEFAULT NULL,
  `file_type` varchar(10) DEFAULT NULL COMMENT 'image/video/file',
  `send_time` datetime DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  KEY `idx_conv_id` (`conversation_id`,`id`),
  KEY `idx_sender` (`sender_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

**已删除**：`receiver_id`（语义并入 conversation）、`file_id`（僵尸列）、`read_status`（未读改游标）。

### 5. 好友关系（拆分为两个表）

原 `user_relations`（双向两行 + 状态）在本次一并重设计，详见
`problems/08-用户关系表重设计.md`：拆为 `friend_relations`（每对好友一行，`user_id < friend_id`）
与 `friend_requests`（单向申请，`status` 只表达请求生命周期 0/1/2）。

## 索引清单与对应查询

| 索引 | 服务查询 |
|------|----------|
| chat_messages(idx_conv_id) | 会话历史游标分页、会话内最大 id、未读计数 |
| chat_messages(idx_sender) | 按发送者查消息（辅助） |
| conversation_members(uk_conv_user) | 成员 upsert 冲突、已读更新定位行 |
| conversation_members(idx_user) | 我的全部会话、未读聚合的 member 提物 |
| users(idx_status) | 在线用户列表 / 在线人数 |
| friend_relations(uk_pair) | 好友列表、是否好友 |
| friend_requests(idx_to_status) | 待处理申请列表 |
| friend_requests(uk_from_to) | 申请 upsert 冲突 |

## 旧 → 新 表映射

| 旧 | 新 |
|----|----|
| chat_messages.receiver_id = 0（群聊） | conversations(type=2, id=1) + conversation_members |
| chat_messages.receiver_id = X（私聊某一段） | conversations(type=1)（按用户对唯一）+ conversation_members |
| chat_messages.read_status | conversation_members.last_read_msg_id |
| chat_messages.file_id | 删除 |
| chat_messages.content 内 JSON 文件元数据 | 拆到 file_url/file_name/file_size/file_type |
| user_relations 双向两行（status=1 已添加） | friend_relations 每对好友一行（归一化） |
| user_relations 单向 status=0 / 3 待处理 | friend_requests 单行（from → to） |
| users.status | 不变 + idx_status |
